# Хранение ключей в базе данных

[English](databases.md) | **Русский**

`--db` принимает одну строку подключения и по ней решает, какое хранилище
открыть. Без флага ключи по-прежнему пишутся папками.

```bash
onion-gen -F abcd --db keys.db                                  # файл SQLite
onion-gen -F abcd --db sqlite://keys.db                         # то же самое
onion-gen -F abcd --db postgres://user:pass@host:5432/onion     # PostgreSQL
onion-gen -F abcd --db mysql://user:pass@host:3306/onion        # MySQL
```

Мастер принимает тот же флаг, и там от него больше всего толку: все находки
флота пишет один мастер.

```bash
onion-gen -F abcd master --listen :8080 --db postgres://user:pass@db/onion
```

Пароль никогда не попадает в то, что печатает программа: и в строке запуска, и
в сообщении об ошибке он заменён на `***`.

## Что выбрать

| Хранилище | Находок в секунду | Что нужно |
|---|---|---|
| папки | 162 | ничего |
| SQLite | 244 000 | ничего |
| PostgreSQL | 32 000 | сервер |
| MySQL | 22 700 | сервер |

Измерено через `cargo bench --bench store-rate`; серверы были контейнерами на
той же машине, так что по настоящей сети будет медленнее, а порядок не
изменится.

Папка на ключ — это каталог, три файла и `fsync`. Одна RTX 4060 на
четырёхсимвольном фильтре находит около 950 ключей в секунду, чего папки не
принимают, а любое из трёх остальных хранилищ принимает. Программа считает
ожидаемую частоту при запуске и говорит её вслух.

Сервер нужен, когда ключи читает больше одного потребителя, когда они должны
лежать там, где уже настроено резервное копирование, или когда иначе
единственная копия будет у мастера флота. В остальных случаях — SQLite: это
файл, ему не нужна учётная запись, и он быстрее всех четырёх.

## Какая схема

Одна таблица, одинаковая по смыслу во всех трёх базах:

| Столбец | Что в нём |
|---|---|
| `address` | полное имя `.onion`, он же первичный ключ |
| `secret_key` | base64 файла `hs_ed25519_secret_key`, вместе с заголовком |
| `public_key` | base64 файла `hs_ed25519_public_key` |
| `filter` | фильтр, по которому совпало, как он был написан |
| `score` | оценка находки |
| `found_at` | unix-секунды |
| `block`, `scalar_offset` | где в поиске находится этот ключ |
| `source` | каким движком найден |

Ключи лежат в base64, потому что их байты — не текст; ровно по той же причине
так записывают ключ SSH. Поэтому строка превращается обратно в файлы для tor
одним `base64 -d` и больше ничем:

```bash
address=$(psql -tAc "select address from onion_keys order by score desc limit 1")
mkdir -m 700 "$address"
psql -tAc "select secret_key from onion_keys where address = '$address'" \
  | base64 -d > "$address/hs_ed25519_secret_key"
psql -tAc "select public_key from onion_keys where address = '$address'" \
  | base64 -d > "$address/hs_ed25519_public_key"
echo "$address" > "$address/hostname"
chmod 600 "$address"/*
```

Таблица называется `onion_keys`, а не `keys`, потому что `keys` —
зарезервированное слово в MySQL.

## Миграции

Вторая таблица, `onion_gen_migrations`, хранит, какие шаги схемы уже
выполнены: `version`, `name`, `applied_at`. Каждый запуск сверяется с ней и
применяет недостающее, поэтому первый запуск на пустой базе создаёт схему, а
все следующие не находят работы.

У каждой базы свой список шагов, потому что диалекты расходятся в типах —
`DOUBLE PRECISION` против `DOUBLE` против `REAL`, — а нумерация версий общая,
так что «схема 1» означает одну и ту же форму везде.

Миграции ничего не удаляют и не переписывают. Столбец, переставший
использоваться, остаётся на месте.

## Заведение PostgreSQL

Отдельная роль и отдельная база, чтобы утечка пароля стоила ключей и ничего
сверх того:

```sql
CREATE ROLE onion_gen LOGIN PASSWORD 'что-нибудь длинное и случайное';
CREATE DATABASE onion OWNER onion_gen;
```

Этого достаточно: как владелец, роль создаст свои таблицы при первом запуске.

Если владеть базой роль не должна — вариант строже, когда базу создаёт
администратор, а программа только пишет, — запустите программу один раз ролью,
которой можно создавать таблицы, а потом сузьте права:

```sql
-- администратором, после того как первый запуск построил схему
REVOKE CREATE ON SCHEMA public FROM onion_gen;
GRANT USAGE ON SCHEMA public TO onion_gen;
GRANT SELECT, INSERT ON onion_keys TO onion_gen;
GRANT SELECT ON onion_gen_migrations TO onion_gen;
```

`SELECT` нужен наравне с `INSERT`: перед тем как принять находку, программа
спрашивает, нет ли такого адреса уже, — чтобы повтор был замечен, а не посчитан
дважды. Она никогда ничего не обновляет и не удаляет.

Чем узкий вариант платит: применить миграцию программа больше не сможет, и
версию, которая её добавляет, придётся сперва пропустить администратором. Если
нет особой причины, берите первый вариант.

Строка подключения:

```
postgres://onion_gen:длинный%20пароль@db.internal:5432/onion
```

Пароль с символами, которые что-то значат в URL — `@`, `/`, `:`, `?`, `#`, —
нужно закодировать процентами. Пароль из одних букв и цифр снимает вопрос.

TLS используется, когда его требует сервер; клиент несёт свои корневые
сертификаты, системный OpenSSL ему не нужен. Чтобы потребовать TLS, добавьте
`?sslmode=require`.

## Заведение MySQL

```sql
CREATE DATABASE onion CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
CREATE USER 'onion_gen'@'%' IDENTIFIED BY 'что-нибудь длинное и случайное';
GRANT SELECT, INSERT, CREATE, INDEX ON onion.* TO 'onion_gen'@'%';
```

`CREATE` и `INDEX` нужны первому запуску, который строит схему. Потом их можно
забрать — с той же оговоркой, что и выше:

```sql
REVOKE CREATE, INDEX ON onion.* FROM 'onion_gen'@'%';
```

Сравнение строк важно. Адрес записан в base32, и два адреса, различающиеся
только регистром, — это два разных адреса; при сравнении без учёта регистра
первичный ключ счёл бы их одним. Схема ставит `utf8mb4_bin` на саму таблицу,
поэтому база, созданная с другим сравнением, всё равно работает правильно, — но
если задать его и базе, всё добавленное позже останется согласованным.

Строка подключения:

```
mysql://onion_gen:пароль@db.internal:3306/onion
```

## Заведение SQLite

Заводить нечего. Файл создаётся, если его нет, вместе с недостающими
каталогами, и сужается до владельца в тот момент, когда появляется, — до того,
как в него что-то записано.

Открывается он в режиме WAL с `synchronous=FULL`, поэтому рядом появляются ещё
два файла, `-wal` и `-shm`. Все три — одно целое: копировать только файл базы
во время работы программы значит скопировать неполную базу.

## Что и когда пишется

Находки идут пачками: тысяча штук или одна секунда — что наступит раньше.
Ради этого база и нужна: тысяча строк делит одну транзакцию и один сброс на
диск.

Это же — единственное, что о ней надо знать. Находка печатается, когда найдена,
и сохраняется в пределах секунды, так что процесс, убитый внутри этой секунды,
теряет то, что держал. Любой обычный выход сбрасывает буфер, и достижение
`--limit` тоже.

Уже сохранённый адрес не пишется второй раз и не считается ошибкой. Программа
спрашивает до того, как принять находку, — именно это держит счётчик находок
честным, когда мастер выдаёт диапазон повторно после истечения аренды.

## Метрики

Мастер публикует то, что делает его хранилище, с меткой вида:

| Метрика | Что значит |
|---|---|
| `onion_gen_store_connections` | открытых соединений; файл считается за одно |
| `onion_gen_store_connections_idle` | из них не занятых |
| `onion_gen_store_rows_total` | записанных ключей; повтор не считается |
| `onion_gen_store_bytes_total` | записанного ключевого материала, 160 байт на ключ |
| `onion_gen_store_batches_total` | зафиксированных пачек |
| `onion_gen_store_failures_total` | пачек, которые хранилище отвергло |

Тревогу стоит вешать на `onion_gen_store_failures_total` больше нуля: флот,
чей мастер не может писать, теряет уже оплаченные ключи. Падение числа
соединений до нуля означает, что сервер пропал.

Метка — фиксированное слово: `directory`, `sqlite`, `postgres`, `mysql`, — и
никогда ничего из строки подключения, так что имя хоста не утечёт в то, что
собирает метрики.

## Безопасность

В базе лежат секретные ключи. Кто может прочитать `secret_key`, тот владеет
этими адресами навсегда.

- Заводите учётной записи отдельную базу, не общую с чем-то ещё.
- Не коммитьте строку подключения. Передавайте её через `ONION_GEN_DB` или
  Secret в Kubernetes, а не в командной строке, где её прочитает всё, что может
  посмотреть список процессов на узле.
- Резервируйте базу так же, как резервировали бы папки с ключами, и берегите
  копии так же.
- Файл SQLite создаётся с правами `0600`. Пусть таким и остаётся; помните, что
  в файле `-wal` лежит тот же материал.
