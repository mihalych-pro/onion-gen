# Движок поиска

[English](search-engine.md) | **Русский**

Этот документ описывает, как движок порождает кандидатов и как решает, кого из
них оставить.

Измеренные скорости приведены в [README](../../README.ru.md).

## 1. Кандидаты — не независимые ключи

Поиск по независимым ключам стоил бы одного скалярного умножения на кандидата.
Этот движок так не делает никогда. Каждый кандидат — это предыдущая точка плюс
константа, поэтому вся пачка стоит одного обращения в поле, а не обращения на
каждого кандидата. Это пакетное обращение Монтгомери, и для программы такого
рода это цена входа.

На процессоре программа несёт два движка и выбирает между ними при запуске.

**Парный движок, `src/pairs.rs`, идёт по скалярному пути.** Он держит таблицу
аффинных смещений `Q(m) = 8m·G` и читает из одной базовой точки `P` сразу двух
кандидатов. На кривой Эдвардса сумма и разность делят дорогие члены:

```text
y(P+Q) = (x1y1 - x2y2) / (x1y2 - y1x2)
y(P-Q) = (x1y1 + x2y2) / (x1y2 + y1x2)
```

Умножения здесь только `x1y2` и `y1x2`. Произведения `x1y1` и `x2y2` хранятся
вместе с точками. Поэтому два умножения дают двух кандидатов — против примерно
восьми на одно сложение точек, — а базовая точка сдвигается раз в раунд, а не
раз на кандидата.

**Цепочечный движок, `src/batch.rs`, идёт по векторному пути.** Он платит полное
сложение точек за каждого кандидата и обрабатывает четырёх кандидатов по
векторным полосам. См. [simd.ru.md](simd.ru.md).

Шаг между кандидатами равен 8. Клэмпинг требует, чтобы младшие три бита скаляра
оставались нулями, а кратное восьми их не трогает.

## 2. Проверка совпадения не строит адрес без нужды

Вывод адреса стоит контрольной суммы SHA3-256, кодирования base32 и выделения
памяти в куче. Для почти каждого кандидата движок избегает всех трёх.

**Первая проверка идёт, пока кандидат ещё четыре лимба в регистрах.**
`FilterSet::leading_probe` строит зонд по старшим битам. Первые восемь байт
канонической формы — это первый лимб, а канонизация меняет его не более чем
двумя вычитаниями модуля. Поэтому зонд, проверяющий все три формы, может
сказать «нет» и никогда не скажет «нет» ошибочно.

**Следующая проверка читает упакованный открытый ключ.** Первые 49 символов
адреса выходят прямо из него. Почему диапазон обрывается на 49 — в
[progress-and-resume.ru.md](progress-and-resume.ru.md).

**Адрес строится только для уцелевшего кандидата.** Фильтр, который дотягивается
дальше ключа, предварительно отсеивается по ключу и подтверждается по полному
адресу; это случается слишком редко, чтобы иметь значение.

## 3. Поле откладывает то, что может отложить

`fiat-crypto` умножает несведённые операнды. Поэтому переносить после каждого
сложения и снова расслаблять перед умножением — чистая трата. Сложение и
вычитание в поле оставляют результат несведённым, а каноническая редукция
выполняется только там, где кодировка обязана быть точной.

## 4. Индекс и точная проверка

Битмап-индекс говорит, что кандидат *может* совпасть. Дальше что-то должно
сказать, с каким именно фильтром, и этот второй шаг определяет стоимость при
большом числе фильтров.

**Фильтры лежат в корзинах по длине.** Каждая корзина держит отсортированный
массив 64-битных префиксов ключа, поэтому попадание в битмап стоит одного
двоичного поиска на каждую различную длину. В словаре одна-две длины, а не
пятьдесят.

**Ниже 64 фильтров программа обходит списком.** При таком размере массивы
помещаются в кеш, а обходу нечего платить за промахи предсказателя переходов.

**Ширина индекса следует за набором фильтров.** Она не фиксирована. Как
программа её выбирает и почему два вида индекса выбирают по-разному — в
[form-indexes.ru.md](form-indexes.ru.md).

Отсортированная проверка спасает и случай, которому индекс помочь не может.
Тысяча двухсимвольных фильтров насыщает любой индекс, и программа его
отбрасывает. Тогда всю проверку совпадения несёт на себе отсортированный поиск.

## 5. Словарь — самый сильный рычаг

Тысяча имён поднимает частоту попаданий в тысячу раз, а это стоит двух символов
префикса. Ни одна оптимизация ядра поиска к этому не приближается, поэтому
потолок размера словаря — вопрос продукта, а не любопытства.

Миллион имён загружается за доли секунды и почти ничего не стоит против тысячи.
Поэтому на практике добавление фильтров бесплатно, и словарь стоит своего
полного множителя.

## 6. Корректность

- **Побайтовая совместимость вывода.** Писатель принимает 16 каталогов ключей,
  созданных `mkp224o`, и все три файла совпадают в точности —
  `tests/mkp224o_compat.rs`.
- **Независимый проверяльщик подтверждает ключи.** `verify-onion-address.py` не
  делит с генератором ни строчки кода. Он заново вычисляет адрес из открытого
  ключа и открытый ключ из секретного скаляра. См. `tests/end_to_end.rs`.
- **tor принимает ключи.** Каталог сервиса, где лежит только
  `hs_ed25519_secret_key`, отдаётся tor с `DisableNetwork 1`. tor заново
  порождает открытый ключ и файл `hostname` и выдаёт ровно тот адрес, о котором
  сообщил генератор.
- **Дифференциальный тест против `curve25519-dalek`** покрывает написанный
  вручную групповой слой, так что тонкая ошибка в нём всплывает в наборе тестов,
  а не в чьём-то живом сервисе.
- **Тест против напечатанного адреса.** `tests/matching_finds_everything.rs`
  ищет в готовом адресе обычным строковым поиском. Сравнение нашего кода с
  другим нашим же кодом не найдёт ошибку, общую для обеих сторон.

## 7. Чего движок не делает

- **Он ничего не публикует.** Любая проверка через tor идёт с
  `DisableNetwork 1`. Объявить дескриптор — это осознанное действие, а не шаг
  тестирования.
- **Он не пишет ключи с устройства.** Устройство сообщает позиции, а ключ
  выводит хост. См. [cuda-path.ru.md](cuda-path.ru.md).
